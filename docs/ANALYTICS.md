# Analytics v1

Analytics is a read-only GraphQL module. `platformAnalytics` requires an authenticated Main console SuperAdmin session. `tenantAnalytics` derives the SUB tenant from the authenticated session and uses `ANALYTICS_VIEW_TENANT` when present; otherwise `ANALYTICS_VIEW_OWN` restricts every Article, ArticleView, and ArticleShare query to `Article.createdByUuid = session.userId`. Neither query accepts a tenant or author ID from the browser. The current product has only the built-in SUPERADMIN, ADMIN, and EDITOR roles; custom roles require a separate authentication and role architecture change. The analytics service itself chooses tenant versus own scope from permissions, not role labels.

All periods use UTC calendar days with an inclusive start and exclusive end. Presets cover 7, 30, 90, 180, or 365 days, including today. Custom ranges are limited to 366 days. Previous-period comparisons use an immediately preceding interval of identical duration. A percentage change is null when the previous value is zero. Points group by UTC day, Monday-start week, or month according to range length.

Platform totals come from non-deleted SUB tenants and non-deleted users with a SUB membership. Tenant growth uses `Tenant.createdAt`. Tenant activity means the count of recorded tenant audit actions in the period; it is not a count of visits or active users. The Main response contains aggregate counts and tenant names only, never tenant Article bodies or review comments.

Tenant and own current status counts use `Article.status`. Publishing activity uses the latest `Article.publishedAt`, including articles subsequently unpublished; re-publication overwrites that timestamp, so it is not a complete history of every publication action. Period views and shares count existing valid `ArticleView` and `ArticleShare` records. Share actions are initiated actions, not confirmed social-media posts. Top Article rankings use period event counts, not lifetime counters or a score. Category, subcategory, and tag rankings attribute each Article's period engagement to its current classification; an Article with multiple tags contributes to each tag. Breaking and Featured counts use current flags, with period engagement from Articles carrying those flags now; they do not prove a flag caused engagement. Own analytics never returns tenant-wide classifications, review metrics, or author activity.

Review actions come from `ArticleReview.decision` in the period. Average review hours pair each completed `CHANGES_REQUESTED` or `APPROVED` decision with the immediately preceding `SUBMITTED` record for that Article; only cycles decided in the selected period enter the average. Missing or incomplete cycles are excluded. Author activity groups authored Articles by display name and counts current records created, submitted, or carrying a `publishedAt` date in the period. No email, visitor key, or IP is returned.

The service reads operational tables directly and adds only indexes for tenant/date review and audit scans and tenant/author publishing reads. Event queries are date bounded; rankings and activity lists have fixed limits; list projections omit content and credentials. No analytics cache is added, avoiding cross-tenant or cross-scope cache sharing. Popular News and public tracking behavior are unchanged.

Unsupported metrics are intentionally omitted: module adoption (`TenantModule` is absent), storage bytes (uploads have no tracked byte metadata per tenant), active users, geography, device, traffic source, reading time, and bounce rate. Future module analytics should contribute separate sections without changing the generic platform overview.
